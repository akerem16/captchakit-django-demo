# Deploying to Render

The repo contains a [Blueprint](https://render.com/docs/blueprint-spec) (`render.yaml`)
that creates two free resources in Frankfurt:

| Resource | What |
|---|---|
| `captchakit-django-demo` | Python web service: `uv sync`, `collectstatic`, then `migrate` + gunicorn with 2 workers. Health check: `/healthz`. |
| `captchakit-demo-kv` | Key Value (Redis-compatible) instance. `ipAllowList: []` means no access from the internet; the web service reaches it over Render's private network. |

Environment variables set by the Blueprint:

- **`DJANGO_SECRET_KEY`**: generated by Render (`generateValue`).
- **`DJANGO_DEBUG=false`**
- **`REDIS_URL`**: the Key Value connection string (`fromService`).
- **`TRUSTED_PROXY_COUNT=1`**: the API rate limit reads the client IP from the last `X-Forwarded-For` entry.
- **`CAPTCHA_TTL`** and **`CAPTCHA_MAX_ATTEMPTS`**

`ALLOWED_HOSTS` and `CSRF_TRUSTED_ORIGINS` pick up `RENDER_EXTERNAL_HOSTNAME`, which Render sets automatically.

## Steps

1. Sign in at <https://dashboard.render.com> with GitHub.
2. **New +** → **Blueprint**.
3. Connect the `akerem16/captchakit-django-demo` repository. Give GitHub access to this repository only if asked.
4. Render reads `render.yaml` and lists the web service and the Key Value instance. Enter a Blueprint name (e.g. `captchakit-demo`) and click **Deploy Blueprint**.
5. Wait for the first deploy. The build takes a few minutes, and the deploy is live when `/healthz` returns 200.
6. Open `https://<service>.onrender.com/` and try the register form and `/api/docs/`.

Every push to `main` redeploys (`autoDeployTrigger: commit`).

## Free tier limits

- **The web service sleeps** after 15 minutes without traffic. The next request wakes it in about a minute, and Render shows a loading page meanwhile.
- **Key Value is in memory only** on the free plan, so a restart wipes it. Only short-lived captchas and rate-limit buckets live there, so nothing important is lost.
- **The disk is ephemeral.** SQLite (`db.sqlite3`) is reset on every deploy, restart or spin-down, so registered users disappear. That is acceptable for a demo. Free Render Postgres is not used because it expires after 30 days.

## Troubleshooting

- **Redirect loop:** the app trusts `X-Forwarded-Proto` from Render's proxy. If pages keep redirecting, set `DJANGO_SECURE_SSL_REDIRECT=false`; Render already redirects HTTP to HTTPS.
- **Every client is rate limited together:** the API rate limit then sees the proxy's IP instead of the client's. Adjust `TRUSTED_PROXY_COUNT`.
- **Health check fails:** open the service's **Logs** tab. `/healthz` returns a JSON body that names the failing dependency (`database` or `redis`).
